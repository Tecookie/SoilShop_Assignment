# Domain documentation

Use one domain context for this assignment.

Before exploring or writing a specification, read root `GLOSSARY.md` and relevant decisions in `docs/adr/` if they exist. Proceed when they do not exist.

Use glossary terminology consistently. Keep implementation details out of the glossary. Create ADRs only for meaningful trade-offs whose rationale future readers need.

Store project documentation in `docs/`, diagram sources in `docs/diagrams/`, and rendered images in `docs/diagrams/images/`.
